# Mac Pro 2013 (D500, amdgpu-x21): plan of 2026-11-13

Rule for every item: fix at the cause, in source, as a patch in its component
(illumos-gate module, gfx-drm, oi-userland, oi-gnome), with an upstream
target. No hand-swapped binaries, links, site services or config workarounds
left in place. The result is installed on the Mac only as IPS packages, in a
new BE built from packages alone, which then becomes the default.

Owners: **R** = Radeon session (amdgpu / drm kernel side), **M** = Mac Pro session.

## 1. Console on the amdgpu display (wscons)  [R]

Boot log: `tem: terminal emulator: Compatible fb not found`,
`consconfig: terminal emulator failed to initialize`.

- amdgpu's DRM fbdev emulation must register with illumos as the console
  framebuffer (gfx_private / visual_io for tem), so wscons, the boot text,
  `/dev/fb` and the VTs (`/dev/vt/*`) exist again on the D500.
- With VTs back, X runs on a VT: no `/dev/fb` fallback, no fight with
  conskbd/consms over the HID streams.
- Upstream: gfx-drm (illumos-drm), plus any illumos-gate part in
  gfx_private/consconfig.

## 2. Window drag freeze (vblank) and DP audio  [R]

One cause (traces 01:07 and 01:11): after X's mode set, DRM sees the Dell's
CRTC as off (all six CRTCs disabled; no SETCRTC turning CRTC 44 back on), so:
no vblank, no page-flip events (mutter waits, the drag freezes; glxgears hides
it), and `audio_enable 0` (Dell silent).

1. Trace SETCRTC with mode_valid and return values, PAGE_FLIP, GETCRTC at an
   X start; find why the enabling SETCRTC is missing or fails; fix in
   drm_core / amdgpu (DCE6).
2. Then DP audio clock: measured 39 897 Hz = 48 000 x 0.831; fix the
   DCE6 audio DTO (`dce_v6_0_audio_set_dto`, phase/module vs. the real
   reference clock).
3. Test: window drag without glxgears, `audiotest /dev/dsp2` audible at the
   right pitch on the Dell.

## 4. USB disks  [M]

- Seagate Portable (USB 3) drops right after attach: `scsa2usb must be
  updated to use usb_pipe_xopen()`, then `Device is gone` / `drive offline`.
  Fix: scsa2usb uses `usb_pipe_xopen()` (USB 3 endpoint companion); test with
  the Seagate and the TOSHIBA. Upstream illumos-gate.
- From the 11-12 work, still open: GPT `is_mounted`, ESP ignore (V_SYSTEM),
  hotplug, `rmumount` sending STOP UNIT, sd START UNIT. The `hal-ntfs`
  branch becomes illumos-gate patches (HAL is in illumos-gate).

## 5. Input and device handover  [M]

- X stays on HAL hotplug (`AutoAddDevices` on). HAL must pick up hotplugged
  HIDs: the Lenovo keyboard (hid2) was never added after re-enumeration. Fix
  in HAL (illumos-gate `hald` solaris backend). The Apple BT HID proxy
  (hid4) "Read error: Error 0" flood: fix the mouse driver's read loop on
  EOF/hangup (xf86-input-mouse sun code) or HAL's input filter.
- Remove `/etc/X11/xorg.conf.d/30-console-input.conf` once that works and
  item 1 gives X its VT.
- logindevperm/gdm: the console user gets `/dev/kbd`, `/dev/mouse`,
  `/dev/usb/hid*`, `/dev/sound/*` at login (plan 1b of 11-12).

## 7. Xorg / Mesa / libdrm packaging  [R + M]

- Done tonight (M): `patches/39-no-console-fb.patch` in the xorg-server 21.1.25
  component: without VTs and without a visual_io `/dev/fb`, X runs without
  a console device instead of failing or holding the DRM node. Ends the
  `/dev/fb -> /dev/null` link and the `fbnull` site service. Built on the VM.
- Mesa `u_screen.c` DETECT_OS_SOLARIS dma-buf cap: patch in the mesa-26
  component (upstream Mesa).
- libdrm `amdgpu_bo_import` size fallback: patch in gfx-drm libdrm (upstream
  libdrm); kernel: `lseek(SEEK_END)` on a dma-buf fd = size (gfx-drm).
- xf86-input-hotkey rebuilt for the 21.1 ABI (back in place, not moved aside).
- [R] `/etc/logindevperm`: the DRM line is
  `/dev/vt/console_user 0600 /dev/dri/* driver=i915,radeon`; add
  `amdgpu` (and check i915n's driver name). The file is illumos-gate's
  (`usr/src/cmd/.../logindevperm`, SUNWcs), so the fix goes to
  illumos-gate; device handover itself needs VTs (item 1: without VTs
  `/dev/vt/console_user` is only a link to `/dev/console`).
- [R] libdrm: ship `data/amdgpu.ids` at `/usr/share/libdrm/amdgpu.ids`
  (gfx-drm libdrm build and manifest; marketing names, glxgears/Mesa warn
  without it). Upstream: gfx-drm.
- [R] Mesa `src/util/os_file.c` `os_same_file_description()`: only Linux's
  kcmp(KCMP_FILE); elsewhere -1 and the amdgpu winsys warns ("couldn't
  determine if two DRM fds reference the same file description"). On
  illumos our DRM core gives every open its own clone minor, so two fds
  share a file description exactly when fstat() gives the same st_rdev
  (and st_dev): implement that for illumos, patch in the mesa-26
  component. Upstream candidate (Mesa).
- xf86-input-keyboard/mouse: the temporary PKG_CONFIG_PATH lines become
  proper component changes.
- Xorg component: pkglint clean (libdrm from gfx-drm), the
  `/usr/X11/include/xorg` link TODO.
